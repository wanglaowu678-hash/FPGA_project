# 提示词：把技能包迁移到新题目

## 适用场景

- 新题目不是“摄像头 → 颜色分割 → 形态学 → 质心”，但仍然是 FPGA/SoC 实时处理；
- 想知道哪些组件能直接复用、哪些必须重写；
- 需要向队友/评委说明“复用边界”，而不是声称“什么都能做”；
- 换板卡、换输入输出、换算法，但保留工程方法和验证流程。

## 使用方法

1. **先分类**：用下面的表判断题目属于哪一类，得到复用等级 A/B/C；
2. **列流水线**：把新题目拆成 5 级（输入 → 缓存 → 核心算法 → 后处理 → 输出）；
3. **查矩阵**：对照 README §1.1 的跨题目复用矩阵，标出“直接用/替换/新写”；
4. **填迁移表**：每一级都写验证方法，避免“代码搬完了但不知道怎么证明它对”；
5. **先做最小闭环**：输入能进、结果能出、有一个已知答案的测试向量，再替换算法。

## 题目分类与复用等级

| 类型 | 典型输入/输出 | 复用等级 | 可直接复用的部分 |
|---|---|---|---|
| 视觉/视频 | 摄像头/HDMI → 显示/跟踪结果 | A（80%+） | 几乎全部 |
| 工业视觉/检测 | 相机 → 缺陷/尺寸/位置 | A（70%+） | 数据流、形态学、质心、脚本 |
| 信号处理/测量 | ADC → FFT/峰值/频率 | B（40~60%） | 数据流模板、模块卡、时序/资源、报告/复现脚本、上板 0-2/10-12 |
| 电机/运动控制 | 编码器/ADC → PWM | B（30~50%） | 时序/资源、CDC、复位、上板 0-2/12、报告/复现脚本 |
| 通信/接口 | UART/SPI/I2C/以太网 | B（40~60%） | CDC、位宽、UART 检查、时序/资源、上板 0-2/10/12 |
| AI 推理/加速 | 图像/张量 → 分类/检测 | B（40~60%） | PYNQ 提示词、时序/资源、报告/复现脚本、上板 0-2 |
| 仪器/人机交互 | 传感器 → 显示/按键 | C（30~50%） | 上板清单、UART、显示时序、模块卡 |

> 等级含义：
> **A** = 改参数/换接口即可；**B** = 保留工程层，算法层重写；**C** = 只保留检查表和脚本。

## 新旧阶段映射表（复制填写）

| 新题目阶段 | 旧技能包对应 | 处理方式 | 验证方法 | 风险 |
|---|---|---|---|---|
| 输入/采样 | camera capture + 帧缓存 | 复用结构，换接口 | 已知测试向量 | 采样时钟/位宽 |
| 缓存/分帧 | 双端口 BRAM / 行缓存 | 复用或换 FIFO | 读写回环 | 跨时钟域 |
| 核心算法 | RGB→HSV / 阈值 | 新写 | 与软件参考对比 | 定点误差 |
| 后处理 | 腐蚀/膨胀 | 新写或删掉 | 边界用例 | 延迟/资源 |
| 输出 | VGA / UART | 复用适配层 | 示波器/串口 | 格式/时序 |

```text
你是一名 FPGA/SoC 系统工程师。请把现有的“实时视觉流水线技能包”迁移到下面这个新题目。
不要假设新题目和视觉相同；先分类，再决定复用哪些组件。

【新题目】
- 题目名称：{topic}
- 输入：{inputs}
- 输出：{outputs}
- 实时性要求：{latency_throughput}
- 目标板卡/器件：{board}
- 工具链：{vivado | quartus | vitis | pynq}
- 关键指标：{metrics}

【现有技能包】
- 组件清单：{components}
- 已验证范围：{validated_scope}
- 已知失效条件：{failure_conditions}

【约束】
- 不能改动的接口：{fixed_interfaces}
- 可用资源：{resources}
- 团队已有基础：{team_background}

请输出：
1. 题目分类与复用等级（A/B/C），说明判断依据；
2. 新旧阶段映射表：阶段 | 复用组件 | 需要新写 | 验证方法 | 风险；
3. 最小可验证闭环：先做哪一级、输入什么、期望输出什么、通过标准；
4. 三个最可能失效的假设（例如“采样率足够”“延迟可忽略”“单时钟域”）；
5. 明确列出“不应复用”的组件及原因。
```

## 示例一：视觉 → ADC/FFT 测量

| 新阶段 | 旧对应 | 处理 |
|---|---|---|
| ADC 采样 | 摄像头捕获 | 换接口，保留“有效信号 + 时钟”结构 |
| 采样缓存 | 帧缓存 | 改为 FIFO/BRAM，注意跨时钟 |
| 窗函数 + FFT | RGB→HSV | 新写；用已知正弦测试 |
| 峰值检测 | 阈值/形态学 | 新写；用双音测试 |
| 频率/幅值输出 | 质心/角度 | 新写；与 MATLAB/Python 对比 |

**可复用**：数据流模板、模块卡、时序/资源优化、报告/复现脚本、上板 0-2/10-12。
**不可复用**：HSV、腐蚀/膨胀、质心、CORDIC、行缓存边界条。

## 示例二：视觉 → 电机控制

| 新阶段 | 旧对应 | 处理 |
|---|---|---|
| 编码器/ADC 采样 | 摄像头捕获 | 换接口，保留同步结构 |
| 控制周期寄存器 | 帧缓存 | 改为单周期锁存 |
| PID/FOC | 颜色判定 | 新写；先做开环 |
| 限幅/死区 | 形态学 | 新写；边界测试 |
| PWM 输出 | VGA/UART | 换输出适配层 |

**可复用**：CDC、复位、位宽、时序/资源、报告/复现脚本、上板 0-2/12。
**不可复用**：视觉算法、行缓存、质心、CORDIC。

## 已验证效果

- 用该流程对“信号处理/测量、电机控制、通信接口”三类非视觉题目做了**纸面推演**，
  能产出明确的“保留/替换/新写”清单和最小闭环；
- **没有实际新建这三类工程**，不能声称已经上板验证；
- 对视觉类新题目（换摄像头/换颜色空间），复用矩阵可直接给出 70% 以上的复用项。

## 失效条件

- 新题目需要模拟前端、射频、高压/安全隔离：技能包不覆盖，需另找领域资料；
- 新题目不是流式处理（批处理、CNN 训练、纯软件）：数据流/行缓存模板不适用；
- 工具链不是 Vivado（Quartus/Gowin/ISE）：报告解析和 XDC 检查不适用；
- 闭环控制对延迟/抖动极敏感：需要额外的控制延迟、采样抖动、执行器饱和分析；
- 团队没有新题目的算法参考：先补算法，再谈移植。
