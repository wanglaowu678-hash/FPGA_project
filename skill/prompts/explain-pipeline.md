# 提示词：讲清一条 FPGA 视觉流水线

## 适用场景

- 拿到一个陌生的 FPGA 视觉工程（Verilog/VHDL/HLS/PYNQ），需要快速理解；
- 需要向队友、老师或评委讲清楚“数据从摄像头到输出经过了哪些模块”；
- 需要找出跨时钟域、反馈回路、延迟链等隐藏结构。

## 使用方法

1. 复制下面的模板；
2. 用工程的实际信息替换 `{...}`；信息不全时把知道的填上，让模型列出缺失项；
3. 先要“结构”，再要“细节”——第一轮不要让它逐行讲代码；
4. 如果它开始猜信号名/时钟频率，立刻打断，要求“只基于给定信息”。

## 提示词模板

```text
你是一名 FPGA 视觉流水线工程师。请只根据我提供的信息，讲清下面这个工程的数据流；
信息不足时请明确列出“还缺什么”，不要猜测。

【已知信息】
- 顶层模块：{top_module}
- 输入端口：{inputs}
- 输出端口：{outputs}
- 模块例化列表：{instances}
- 时钟与复位：{clocks_resets}
- 摄像头/输入接口：{camera_interface}
- 显示/输出接口：{output_interface}
- 目标平台：{board_or_fpga}
- 讲解深度：{beginner | intermediate | expert}

【请按以下顺序输出】

1. ASCII 数据流图
   - 从输入到输出，标出每条主数据通路；
   - 标出帧缓存、行缓存、FIFO 等存储节点；
   - 标出反馈回路（如果有），用 ↑/↓ 箭头表示。

2. 时钟/复位表
   | 时钟/复位 | 频率/极性 | 驱动的模块 | 来源 | 备注 |
   若某模块跨时钟域，请在备注里标“CDC”。

3. 模块职责表
   | 模块 | 一句话职责 | 输入 | 输出 | 延迟（拍/行/帧） | 资源类型 |
   延迟不确定就写“未知”，不要编。

4. 关键数据结构
   - 像素格式（RGB565/RGB888/灰度/二值）、位宽、每拍几个像素；
   - 行/场同步信号如何参与地址计算；
   - 行缓存/帧缓存的深度与位宽。

5. 三条最重要的“隐藏关系”
   - 例如：显示图比摄像头晚几拍、质心用的是上一帧结果、角度是组合逻辑算的；
   - 每条都要给出代码依据（模块/信号名）。

6. 风险清单
   - 跨时钟域、组合逻辑除法/乘法、行缓存边界、未初始化寄存器；
   - 每条标“高/中/低”，并说明触发条件。

7. 还缺哪些信息
   - 列出为了讲得更准，我还需要你补充的 3~5 项。
```

## 输出格式要求

- 数据流图用 `text` 代码块，保持等宽对齐；
- 表格用 Markdown；
- 每个结论后面用括号标出来源，例如 `（colorDetect.v:139）`；
- 不确定的地方写“未知”，不要用“应该”“可能”糊过去。

## 已验证效果

在 v_1020（Zynq-7020 + OV7725 + VGA + 三色跟踪）上，该模板一次产出了：

- 从 `OV7725_D` 到 `vga_red/green/blue` 的完整数据流；
- 4 个时钟域（摄像头 PCLK、25 MHz 显示/处理、100 MHz 角度/EEPROM、38400 UART）；
- 2 条反馈回路（形态学 `colorDetect→erode→dilate→colorDetect`、显示 `ram_read→BRAM→HSV→colorDetect/render→ram_read`）；
- 延迟链约 4~6 拍，解释了“显示图比摄像头晚几拍”。

## 失效条件

- 只有零散代码片段、没有顶层例化：无法画数据流，先要顶层文件；
- 工程不是逐像素流水线（帧级批处理、CNN）：行缓存/延迟链部分不适用；
- 模型没有代码访问权限：要求你贴关键模块，否则只能给通用框架。
