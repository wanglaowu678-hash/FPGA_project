# 提示词：二值图 / 质心异常调试决策树

## 适用场景

颜色分割后的二值图或质心出现以下现象：

- 全白 / 全黑；
- 噪点多、边缘毛刺；
- 目标内部有空洞；
- 目标缺失或只检测到一部分；
- 质心乱跳、十字光标跑到原点；
- 角度输出跳变或恒定；
- 串口/数码管数值不对。

## 使用方法

1. 先按下面的决策树**从上游到下游**逐级确认，不要一上来就调阈值；
2. 每一级都有“观察点”和“通过标准”，不通过就停在这一级；
3. 把现象、波形、关键代码贴给模型，让它只分析当前这一级；
4. 找到根因后，用 `checklists/rtl-pitfalls.md` 对应编号的“修复/验证”收尾。

## 决策树

```text
[0] 系统 sanity
    ├─ 时钟/复位是否正确？PLL 锁定？bitstream 加载？
    ├─ 摄像头 I2C 是否读到 ID（OV7725 = 0x42）？
    └─ VGA 时序是否符合 640x480@60？
         不通过 → 先修 bring-up，不要看颜色

[1] 原始 RGB 是否正常？
    ├─ 用测试图案/彩条源，绕过 HSV 和颜色判定
    ├─ 检查 RGB565→RGB888 的位拼接/零填充
    └─ 通过标准：彩条颜色和顺序正确
         不通过 → 查摄像头配置、BRAM 读写、VGA 地址

[2] RGB→HSV 是否正确？
    ├─ 输入纯红/绿/蓝/白/黑，看 H/S/V
    ├─ 纯色期望：红 H≈0，绿 H≈60，蓝 H≈120，白 S≈0，黑 V≈0
    ├─ 检查 max==min 分支：divisor 是否置 1，避免除零
    └─ 通过标准：误差在 ±2 个 H 单位内
         不通过 → 查公式分支、除法器位宽、流水线对齐

[3] 参考色是否正确？
    ├─ 黄框（ROI）是否完整落在目标上？1024 个像素是否都被目标填满？
    ├─ 按按钮后 HSV_detect 是否更新？
    ├─ 上电未按按钮时 HSV_detect 是否为 0（会匹配黑色）？
    ├─ 红色目标是否跨 H=0/179？线性平均是否得到 90（青色）？
    ├─ EEPROM 读入后是否覆盖了按钮/清空？
    └─ 通过标准：参考色 ≈ 目标区域的平均色
         不通过 → 查 ROI 坐标、按钮优先级、hue 环绕、复位

[4] 阈值是否合理？
    ├─ 对目标样本和背景样本分别算加权距离 d = H/2 + S/4 + V/4
    ├─ 单项门槛：H/2≤9，S/4≤15，V/4≤15
    ├─ 总和门槛：d≤24
    ├─ 目标样本通过率是否 >95%？背景样本拒绝率是否 >95%？
    └─ 通过标准：两类样本的 d 分布明显分开
         不通过 → 调权重/门槛，或改用自适应阈值

[5] 形态学是否破坏边界？
    ├─ 行缓存读下标是否越界（h-3 时 h 是否 ≥3）？
    ├─ 帧首 3 行是否用了上一帧的陈旧数据？
    ├─ 消隐期 h=0 是否仍在写第 0 列？
    ├─ 派生时钟是否让换行慢一拍，前几个像素写进旧缓存？
    └─ 通过标准：目标内部干净，左右/上下边界无固定条带
         不通过 → 按 rtl-pitfalls #1~#4 修

[6] 质心是否可信？
    ├─ Binary_Sum 是否大于门限（例如 30）？否则 center 被强制归零
    ├─ 加权质心的 weight 是否基于上一帧 center？center 错了会锁死
    ├─ 质心坐标是否与显示坐标同一帧？差几拍会导致十字偏几像素
    └─ 通过标准：目标缓慢移动时质心平滑跟随，不跳变
         不通过 → 查门限、权重反馈、坐标对齐

[7] 输出是否正确？
    ├─ CORDIC 输入是否缩放溢出（16 位有符号，最大 32767）？
    ├─ angle 位宽是否够（0~358°，8 位会回绕）？
    ├─ UART 发的是原始字节还是 ASCII？波特率分频是否准确？
    ├─ 25 MHz 与 100 MHz 之间是否有同步器？
    └─ 通过标准：已知向量输入 → 已知角度输出；串口字节可解释
         不通过 → 按 rtl-pitfalls #13~#16 修
```

## 提示词模板

```text
你是一名 FPGA 视觉调试工程师。请只分析下面这一级，不要跳到别的阶段。

【当前阶段】{0~7 的编号与名称}
【现象】{例如：二值图左侧 3 列固定为 0}
【关键代码】{贴相关模块/信号}
【波形/测量】{VtcHCnt/VtcVCnt/pix_i/pix_o 的观察}
【已经排除】{例如：原始 RGB 正常、HSV 纯色正确}

请输出：
1. 该现象最可能的 3 个根因，按概率排序；
2. 每个根因的代码级证据（文件:行号）；
3. 一个最小验证实验（改什么、看什么、通过标准）；
4. 如果证据不足，明确列出还需要哪些信息。
```

## 已验证效果

在 v_1020 上，该决策树帮助定位到：

- 二值图左边界异常 → 行缓存 `h-3` 在 `h=2` 越界（第 5 级）；
- 顶部固定异常 → 行缓存未清 + `v>=2` 不够（第 5 级）；
- 红色目标丢失 → H 在 0/179 两端，线性平均偏到 90（第 3 级）；
- 上电全屏误检 → `HSV_detect` 无复位，默认 0 匹配黑色（第 3 级）。

## 失效条件

- 问题不在视觉链路（电源、时钟、DDR、bitstream）：先做第 0 级；
- 没有波形/ILA：只能给假设，不能定论；
- 摄像头不是 DVP：第 1 级的接口检查需替换。
