# 提示词：按时序/资源报告优化视觉流水线

## 适用场景

- Vivado 综合/实现后时序不收敛（WNS/WHS 为负）；
- 资源超预算（LUT/FF/BRAM/DSP）；
- 能跑但频率上不去，想提高像素时钟或分辨率；
- 想知道“先动哪里”而不是盲目加流水线。

## 使用方法

1. 先跑 `scripts/parse_vivado_report.py` 把关键数字提取成表；
2. 把报告里的**关键路径**（start/end、logic levels、net delay）贴给模型；
3. 让模型先分类瓶颈，再给方案；不要接受“多加几级寄存器”这种万能答案；
4. 每个方案都要有“预期收益 / 代价 / 验证方法”。

## 提示词模板

```text
你是一名 FPGA 时序/资源优化工程师。请根据下面的报告，先分类瓶颈，再给方案。

【目标】
- 目标时钟：{fmax_mhz} MHz
- 当前 WNS/WHS：{wns} / {whs} ns
- 资源预算：LUT {lut_budget}，FF {ff_budget}，BRAM {bram_budget}，DSP {dsp_budget}
- 当前利用率：{util_summary}

【关键路径】
- Start：{start_pin}
- End：{end_pin}
- Logic levels：{logic_levels}
- 主要延迟：{net_delay} ns net + {logic_delay} ns logic
- 路径上的模块：{modules_on_path}

【设计背景】
- 像素时钟：{pixel_clk}
- 处理时钟：{proc_clk}
- 是否有组合逻辑除法/乘法：{yes_no}
- 是否有跨时钟域：{cdc_list}

请输出：
1. 瓶颈分类（组合逻辑过长 / 除法器 / 乘法器 / BRAM 端口 / CDC / 高扇出 / 其他），
   并给出判断依据；
2. 按“收益/代价”排序的 3 个方案，每个包含：
   - 改哪个模块/信号；
   - 预期减少几级逻辑或几 ns；
   - 资源代价（LUT/FF/BRAM/DSP）；
   - 对延迟/吞吐的影响；
   - 如何验证（报告指标/仿真/上板）；
3. 一个“最小改动”方案（如果只允许改一处）；
4. 一个“不推荐”的方案及原因（避免我踩坑）。
```

## 常见瓶颈与对策（视觉流水线）

| 瓶颈 | 典型位置 | 对策 |
|---|---|---|
| 组合逻辑除法 | RGB→HSV 的 `/` | 改为流水线除法器；或用倒数乘法；或查表 |
| 组合逻辑乘法 | 坐标缩放、加权 | 用 DSP48 推断；加输入/输出寄存器 |
| 长组合路径 | 16 项 AND/OR、阈值比较 | 插入流水线寄存器；用平衡树 |
| BRAM 端口不足 | 行缓存多读端口 | 用 LUTRAM 复制；或分时复用 |
| 高扇出 | 复位/使能/state | 复制寄存器；用 BUFG；改时钟使能 |
| CDC | 25/100 MHz 交界 | 2FF 同步器；异步 FIFO；握手 |
| 派生时钟 | `always@(posedge Line_CLK)` | 改时钟使能，统一到主时钟 |
| 资源超限 | 三路并行 BW/形态学 | 时分复用；降低并行度；共享除法器 |

## 输出格式

- 先给一张 `瓶颈 | 证据 | 方案 | 预期收益 | 代价` 表；
- 再给“最小改动”；
- 最后给验证命令/报告字段。

## 已验证效果

在 v_1020 上，按该流程识别出：

- RGB→HSV 每像素两个组合除法器是时序/资源热点；
- 形态学 16 项 AND/OR 是长组合路径，可加一级寄存器；
- `always@(posedge Line_CLK)` 是派生时钟，建议改时钟使能；
- 25 MHz 与 100 MHz 之间无同步器，属于 CDC 风险。

## 失效条件

- 没有报告：只能给通用建议，不能定量；
- 目标频率未定：无法判断“够不够”；
- 时序已满足、只是资源超：把重点换成面积优化（共享、时分复用、BRAM 替代 LUTRAM）。
