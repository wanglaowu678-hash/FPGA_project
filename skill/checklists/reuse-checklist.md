# 技能包复用性自检清单

> 用途：在提交/交接前，检查“一个没参与过原项目的人，能不能直接使用这个技能包”。
> 对应竞赛 3.3.5.2 的评审标准：**复用性**。
> 每一项都给出通过标准；不通过就补文档，不要靠口头解释。

## A. 范围与定位

- [ ] **一句话范围**：README 开头能用一句话说清“这个技能包解决什么问题”
- [ ] **适用清单**：列出 5~8 个适用场景（输入、处理、平台、工具）
- [ ] **失效清单**：列出 5~8 个不适用场景，并给出替代做法
- [ ] **跨题目矩阵**：至少覆盖 5 类题目，标出“直接复用/替换/不适用”
- [ ] **复用等级**：明确 A/B/C 三档的含义，不把“通用层”说成“全部通用”

**通过标准**：一个陌生人读完 §1/§2，能判断自己的题目是否在范围内。

## B. 每一项的四要素

对 `prompts/`、`templates/`、`scripts/`、`checklists/` 里的每一项检查：

- [ ] **适用场景**：什么时候用、什么时候不要用
- [ ] **使用方法**：输入什么、按什么顺序做、输出什么
- [ ] **验证效果**：在哪个项目/哪组样例上验证过；是“已执行”“静态分析”还是“纸面推演”
- [ ] **来源**：来自哪次失败/观察（坑编号、案例文件、行号）
- [ ] **失效条件**：什么情况下结论不成立

**通过标准**：随机抽一项，能在 2 分钟内找到上面五项，不需要翻聊天记录。

> 常见问题：只写“使用方法”，不写“验证效果”；只写“通用”，不写“失效条件”。

## C. 陌生队伍可执行性

- [ ] **自测可跑**：`python -I tests/selftest.py` 输出 `9 passed, 0 failed`
- [ ] **无绝对路径**：脚本/文档不写死 `D:\fpgacode\...`、`C:\Users\...`
- [ ] **只用标准库**：脚本不依赖 numpy/pandas 等第三方包
- [ ] **CLI 输出 ASCII**：避免 Windows 控制台 GBK/UTF-8 乱码
- [ ] **有退出码**：0=通过，1=失败，能直接接 CI
- [ ] **有示例输入**：脚本至少有一个可复制的最小样例和期望输出
- [ ] **不绑板卡**：板卡/摄像头型号只作为示例出现，并标明“需替换”
- [ ] **40 分钟闭环**：新人能在 40 分钟内跑通第一个组件（通常是 selftest 或报告解析）

**通过标准**：在一台没装过本项目的电脑上，只照 README 操作，能跑通自测。

## D. 迁移能力

- [ ] 有 `prompts/adapt-to-new-topic.md` 或等价的迁移工作流
- [ ] 有新旧阶段映射表模板（阶段/复用/新写/验证/风险）
- [ ] 有“不应复用”的明确清单
- [ ] 非视觉题目有“最小可验证闭环”的建议
- [ ] 换工具链（Quartus/Gowin）时，明确哪些脚本失效

**通过标准**：给定一个非视觉题目，能在 30 分钟内产出一张迁移表和第一版闭环计划。

## E. 评审前 10 分钟

- [ ] 随机挑一个组件，按 README 的“使用方法”走一遍
- [ ] 跑 `python -I tests/selftest.py`
- [ ] 跑 `python -I scripts/repro_check.py .`
- [ ] 检查 README 没有“万能/100%/完全通用”这类过度声明
- [ ] 检查每个“已验证”都有验证方式（已执行/静态分析/纸面推演）
- [ ] 让一个没参与的人复述：范围、失效条件、第一个该用的组件

**通过标准**：对方能复述三点，且不把“纸面推演”误认为“上板实测”。

## F. 常见扣分点

| 扣分点 | 表现 | 修复 |
|---|---|---|
| 范围过大 | 声称“适用所有 FPGA 题目” | 改成“视觉流水线 + 通用工程层” |
| 没有失效条件 | 只写“怎么用”，不写“什么时候不能用” | 每项补 2~3 条 |
| 验证不可追溯 | 写“效果很好”，没有项目/样例/日期 | 补“已执行/静态分析/纸面推演” |
| 绑定原项目 | 路径、引脚、阈值写死 | 改成参数/模板/示例 |
| 脚本不可跑 | 依赖第三方包、输出乱码 | 改标准库、ASCII 输出、加 selftest |
| 迁移无路径 | 只说“可以复用”，没有映射表 | 加 `adapt-to-new-topic` 工作流 |

## 失效条件

- 技能包还没有抽象，只是原项目的代码压缩包：先重构，再谈复用；
- 没有脚本、只有文档：C 节可跳过，A/B/D/E 仍适用；
- 评审不看文档只看演示：优先准备 5 分钟现场演示（selftest + 一个真实案例）。
