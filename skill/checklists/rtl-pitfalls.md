# RTL 视觉流水线踩坑清单（16 条）

> 使用方式：先看「触发条件」快速筛选，命中后再看「现象 → 根因 → 修复 → 验证」。
> 每条都标了「来源」，说明它是从哪次失败/观察中总结的，方便判断是否适用于你的工程。

---

## A. 行缓存 / 形态学

### #1 行缓存读下标越界（`h-3` 配 `h>=2`）

- **触发条件**：`VtcHCnt == 2`，代码读 `LineBufferX[VtcHCnt-3]`
- **现象**：仿真左边界出现 X；上板左侧 1~2 列有固定异常；综合结果不可靠
- **根因**：`VtcHCnt` 是无符号 12 位，`2-3` 在 32 位表达式中回绕成 `0xFFFFFFFF`，
  远超行缓存的 `0..319` 下标范围（至少也会大于 319）
- **修复**：guard 改成 `VtcHCnt >= 3`；或把窗口改成 `h-2..h+1` 并重新对齐
- **验证**：仿真 h=0..5 无 X；上板左边界无固定条带
- **来源**：v_1020 `erode.v` / `dilate.v`，guard 写 `>=2` 但读 `[VtcHCnt-3]`

### #2 帧首行缓存未清，`v>=2` 不够

- **触发条件**：每帧开始时 `state` 归零，但 4 个 `LineBuffer` 没有清零
- **现象**：每帧最上面 1~2 行出现异常白块/黑块
- **根因**：4×4 窗口需要前 3 行；row 2 时只有 row 0/1 属于当前帧，
  第 4 行来自上一帧，读到的是陈旧数据
- **修复**：帧首清零行缓存；或 guard 改成 `VtcVCnt >= 3`；或给缓存加 valid 标记
- **验证**：连续多帧，顶部边界稳定；换帧时无闪烁
- **来源**：v_1020 形态学模块，`state` 复位但缓存未清

### #3 消隐期仍写行缓存第 0 列

- **触发条件**：`region_cut` 在窗口外输出 `VtcHCnt=0`，行缓存写使能没有门控
- **现象**：左边界第 0 列被反复覆盖；边界腐蚀/膨胀结果异常
- **根因**：消隐期 `h=0`，`LineBuffer[0] <= pix_i` 仍在执行，覆盖上一行列 0
- **修复**：加 `valid` 门控（只在有效像素区写）；或只在 `h < 320` 且行有效时写
- **验证**：ILA 看写使能，消隐期应为 0；左边界无固定异常
- **来源**：v_1020 行缓存写逻辑，写使能常开

### #4 派生时钟导致换行慢一拍

- **触发条件**：`always@(posedge Line_CLK)`，`Line_CLK` 由寄存器在 `h==1` 产生
- **现象**：每行前 2~3 个像素写进旧缓存；左边界条带；时序分析复杂
- **根因**：`Line_CLK` 打一拍，`state` 在 `h≈2` 才切换；同一拍 PCLK 块仍用旧 state
- **修复**：改时钟使能 `if (line_start) state <= ...`，统一到 PCLK 域
- **验证**：换行后第一个像素就写入新缓存；左边界无条带
- **来源**：v_1020 `erode.v` / `dilate.v` 的 `always@(posedge Line_CLK)`

## B. 组合逻辑 / 位宽

### #5 组合逻辑里用非阻塞赋值

- **触发条件**：`always@(*)` 里写 `<=`（如 `BW.v` 的 `H_diff <= ...`）
- **现象**：仿真靠 delta cycle 收敛，可能掩盖竞争；综合忽略区别，但可读性差
- **根因**：非阻塞赋值语义是“本拍末更新”，组合逻辑应即时更新
- **修复**：组合逻辑一律用阻塞赋值 `=`
- **验证**：lint 无警告；仿真结果与手算一致
- **来源**：v_1020 `BW.v` 的 `always@(*)`

### #6 RGB565→RGB888 零填充，最大值不是 255

- **触发条件**：`{rgb565[15:11], 3'b000}` 这类零填充
- **现象**：白色显示为 (248,252,248) 而不是 (255,255,255)；HSV 的 V 最大 248/252
- **根因**：5 位最大值 31 → `11111000` = 0xF8；6 位最大值 63 → `11111100` = 0xFC
- **修复**：需要满量程时用位复制（`{r,r[4:2]}`）；或按 0..248 设计阈值
- **验证**：纯白输入，RGB888 输出应为 0xFF 或明确的 0xF8/0xFC
- **来源**：v_1020 `rgb565_rgb888.v`

## C. 颜色 / 参考色

### #7 HSV 色相环绕，线性平均把红色平均成青色

- **触发条件**：目标红色，H 在 0 和 179 两端；ROI 内同时出现两端
- **现象**：参考色 H≈90（青色），红色目标检测不到
- **根因**：H 是环形量，`(0 + 179)/2 = 89.5`，不是红色
- **修复**：环形距离 `min(|ΔH|, 180-|ΔH|)`；环形平均用 sin/cos 或向量平均
- **验证**：红目标跨 0/179 时，参考色仍接近 0 或 179
- **来源**：v_1020 参考色采样，`H_Sum/1024`

### #8 参考色无复位，上电默认 0（黑色）

- **触发条件**：`HSV_detect` 没有复位/初值
- **现象**：上电未按按钮时，系统把黑色当目标；画面大面积误检
- **根因**：FPGA 寄存器上电为 0，`HSV_detect=0` 表示 H=0,S=0,V=0（黑）
- **修复**：复位到 `0xFFFFFF`（匹配不到任何颜色）；或要求先按按钮
- **验证**：上电后二值图应为空，直到按下采样按钮
- **来源**：v_1020 `colorDetect.v`

### #9 EEPROM 读入标志粘滞，覆盖按钮/清空

- **触发条件**：`data_on*Switch_changed` 置 1 后从不清零
- **现象**：EEPROM 读入一次后，再按采样按钮或清空开关都无效
- **根因**：`else if(data_on*Switch_changed==1 && read_flag)` 一直为真，优先级高于按钮/清空
- **修复**：读取完成后清标志；或用边沿检测代替电平
- **验证**：EEPROM 读入后，按钮/清空仍能改参考色
- **来源**：v_1020 `colorDetect.v` 的优先级链

### #10 清空开关被当异步复位

- **触发条件**：`sw_ColorClear` 同时接 `colorDetect.rst_n` 和 `top_e2prom.sys_rst_n`
- **现象**：按住清空时，ROI 不累加、帧末不求平均，参考色永远不更新
- **根因**：复位期间整个模块停止工作，不只是清参考色
- **修复**：把“清空参考色”和“模块复位”分开；清空只写 `HSV_detect`
- **验证**：按住清空时，ROI 仍能累加；松开后参考色正常更新
- **来源**：v_1020 `design_1.v` 的复位连接

## D. 质心

### #11 质心门限导致十字光标跳到原点

- **触发条件**：`Binary_Sum <= 30` 时 `center_h/center_v` 被强制为 0
- **现象**：目标很小/被遮挡时，十字光标跳到左上角
- **根因**：门限用于过滤噪声，但目标小时会误判为“无目标”
- **修复**：调低门限；加滞回（进入/退出用不同门限）；保持上一帧结果
- **验证**：小目标/短暂遮挡时，光标不跳变
- **来源**：v_1020 `colorDetect.v` 的 `Binary_Sum>30`

### #12 加权质心反馈锁死

- **触发条件**：`weight_cal` 用上一帧 `center_h/center_v` 算权重
- **现象**：初始中心偏了，权重把远处像素压低，质心锁在错误区域
- **根因**：正反馈；中心错 → 权重错 → 新中心更错
- **修复**：首帧用普通质心；限制权重范围；中心偏差过大时重置
- **验证**：人为把初始中心放偏，系统能拉回目标
- **来源**：v_1020 `weight_cal.v` + `center.v`

## E. 角度 / CORDIC

### #13 CORDIC 输入缩放溢出

- **触发条件**：坐标差 `*50` 或 `<<14`，16 位有符号
- **现象**：角度完全错误；仿真溢出；上板跳变
- **根因**：`320 << 14 = 5,242,880` 远超 32767；`*50` 后 16000 才安全
- **修复**：缩放系数满足 `max_diff * scale <= 32767`；或加宽输入位宽
- **验证**：最大坐标差输入，CORDIC 不溢出，角度与 atan2 对照
- **来源**：v_1020 `angle_calculation.v`，注释里保留的 `<<14` 方案

### #14 `angle` 8 位回绕

- **触发条件**：两个方向夹角接近 360°
- **现象**：角度从 255 跳到 0；上位机看到突变
- **根因**：`angle` 是 8 位，最大 255；实际可达约 358°
- **修复**：输出改 9 位；或限制到 0~180；或做饱和
- **验证**：输入两个相反向量，输出应为 180 而不是回绕值
- **来源**：v_1020 `angle_calculation.v` 的 `output reg [7:0] angle`

## F. 时钟 / 输出

### #15 跨时钟域没有同步器

- **触发条件**：25 MHz 视觉域与 100 MHz 角度/EEPROM 域直接相连
- **现象**：偶发亚稳态；角度/读数偶尔错一拍；长时间运行偶发异常
- **根因**：多比特/单比特信号跨域未同步
- **修复**：单比特用 2FF 同步器；多比特用异步 FIFO/握手；加 `set_clock_groups`
- **验证**：CDC 报告无未约束路径；长时间运行无偶发错误
- **来源**：v_1020 `design_1.v`，`clk_wiz_0_clk_out1` 与 `clk100`

### #16 UART 发原始字节，不是 ASCII

- **触发条件**：`uart_tx.data_o` 直接接 `angle` 或坐标
- **现象**：串口助手显示乱码；用户以为波特率错了
- **根因**：发送的是 0~255 的二进制值，不是 '0'~'9' 的 ASCII
- **修复**：先转 ASCII 十进制字符串再发；或上位机按二进制解析
- **验证**：用十六进制模式看，字节值等于角度；ASCII 模式应为数字字符
- **来源**：v_1020 `uart_tx.v` + `design_1.v` 的 `uarttemp`
